# PR-CI-CD-Autonomous-Map

## Why this slice exists

Issue #1962 tracks the work to map Atlas's CI/CD system for long-running
autonomous coding, explain why it works, and turn the lessons into a reusable
playbook. Before optimizing or codifying more checks, the current machine needs
one grounded inventory that names the real local gates, GitHub workflows,
trusted-base PR checks, review/reconciliation gates, and the new long-running
PR watcher contract.

Root cause: the autonomous-coding loop is now spread across `AGENTS.md`,
`CLAUDE.md`, workflow YAML, local audit scripts, and prior operator practice.
That makes it powerful but hard to replicate or safely optimize. This PR fixes
the documentation gap only; it does not change CI behavior.

## Mechanism

The new map is generated by reading the repo's current workflow YAML, local
review scripts, branch-protection audit, security guardrails, and the updated
`AGENTS.md`/`CLAUDE.md` long-running watcher contract. It records the current
system as documentation so later slices can classify required/advisory checks,
measure runtime, and propose speedups against a shared baseline.

## Intentional

- No workflow, branch-protection, or audit-script changes in S1. This prevents
  optimization work from happening before the map is reviewable.
- The map says `scripts/check_required_status_checks.py` audits specific
  required contexts instead of claiming every green PR check is branch-required.
- The workflow inventory records current YAML names/jobs and does not yet rank
  runtime or duplication; that belongs to later slices.
