# PR-OIDC-Closed-Vocabulary

## Why this slice exists

Third round on the same predicate, and the third time it was wrong on a side
nobody had checked. ATLAS #2305 added it, #2310 fixed two holes in it, and this
closes two more that #2310 introduced or left.

Both reproduced by executing the merged code on `main` before any fix:

**1. The scalar catch-all was a fail-open.** `_permissions_oidc_state` returned
`OIDC_WRITE` for `"write"` and `OIDC_NONE` for **everything else**:

```
id-token: 'write'                -> write
id-token: 'none'                 -> none
id-token: 'read'                 -> none
id-token: ''                     -> none
id-token: '${{ inputs.scope }}'  -> none     <-- evades the OIDC check entirely
id-token: 'WRITE'                -> none
```

An unresolved expression, an empty string, or a case variant all read as "no
OIDC request" and skipped the allowlist. That is the same mistake #2310 was
written to fix -- treating *unevaluable* as *absent* -- reintroduced one layer
down, in the catch-all rather than the type check.

**2. A test that could not fail.** `test_enrolled_job_with_list_valued_id_token_is_rejected`
asserted only that *some* ERROR existed, but its fixture trips two independent
branches: the workflow-scope invalid finding and the trusted-base admission
rejection. Deleting the OIDC branch left the test green -- verified by deleting
it. This is the identical masking defect fixed in #2305's guard-shape fixtures
earlier the same day, reintroduced in a new test.

### Why this slice is over the 400-LOC target

Roughly nine tenths of it is not behaviour: the production change is one
if/elif chain in `_permissions_oidc_state`. Per-file figures live in
**Estimated diff size** below, regenerated by `scripts/sync_pr_plan.py`, so they
are not restated here.

The overage is test weight, and deliberately so. This predicate has now failed
review three times, every time on an input class its tests did not cover, and
twice on a fix for the previous failure. The response to that is more reject-side
coverage, not less: an 8-row closed-vocabulary table, an isolated
workflow-scope fixture, and split assertions on the combined fixture. Cutting
the tests to fit the budget would remove the only thing that has reliably caught
these.

Not splittable: the vocabulary fix and the test isolation are one change,
because the isolated test is what proves the vocabulary fix fires. Landing the
vocabulary change with the masked test would repeat exactly the failure this PR
exists to correct.

### Problem-derived contract

- Root cause: a catch-all that maps every unrecognized input to the safe-looking
  answer. Both defects are that shape -- an `else` returning `NONE`, and an
  assertion satisfied by any error.
- Correct fix must touch/change: `_permissions_oidc_state` must recognize a
  CLOSED vocabulary (`write`, `none`) and classify every other scalar
  `OIDC_INVALID`; the combined fixture must assert each branch by its own
  message, and the workflow-scope branch needs a fixture where nothing else can
  produce an error.
- Must not change: `id-token: write` on the owner-gated Claude job stays a WARN,
  `id-token: none` stays silent, and the auditor keeps exiting 0 against the
  real workflow tree.

### Review Contract

1. Only `write` and `none` are recognized; every other scalar is INVALID.
2. `.github/workflows/claude.yml` (`id-token: write`) is unaffected -- the
   auditor still exits 0 against the real tree, so nothing existing is newly

3. The workflow-scope invalid branch has a fixture that fails if and only if

5. The INVALID diagnostic is true for every cause. Widening INVALID to cover

   `read` and `WRITE`, which are perfectly well-formed scalars -- a confidently
   specific message pointing at malformed YAML when the real problem was
   vocabulary. Both messages now read `id-token must be the string "write" or
   "none"`, which is accurate for a list, a mapping, and an unsupported scalar
   alike.
4. The combined fixture asserts both branches by message, not by error count.

Affected surfaces: `_permissions_oidc_state` only. No workflow, no allowlist
entry, no admission predicate, no guard-shape check.

Risk areas: over-rejection on a legitimate value outside the vocabulary. Probed
by grepping every `id-token` occurrence in `.github/workflows/` -- exactly one,
`claude.yml:31: id-token: write` -- and by running the auditor against the real
tree (exit 0). GitHub documents `write` and `none` as the accepted values for
this scope, so the closed set matches the upstream contract rather than a guess.

- Reviewer rules triggered: R2, R3, R10, R13, R14.

R13 because this is a closure declaration change: the recognized-value set moves
from open-with-a-default to closed-with-a-reject.

**boundary-probe:** 8-row vocabulary table -- admit `write`/`none`; reject
`read`, `""`, `${{ inputs.scope }}`, `WRITE`, `Write`, and `"write "` (trailing
space). The case and whitespace rows matter because YAML preserves both and the
previous catch-all silently forgave them.

**Mutation-probe (run, not asserted), two independent probes:**
deleting the workflow-scope invalid branch now fails 2 tests (it failed 0
before this PR); restoring the `else -> OIDC_NONE` catch-all fails 6. Restored
before commit.

**Guard-class closure declaration -- `id-token` recognized values**

- **Member set:** the scalar values `_permissions_oidc_state` recognizes.
- **CLOSED and ENUMERATED:** `write`, `none`, taken from GitHub's documented
  vocabulary for this scope. Not derived, not extensible by a workflow.
- **Out-of-set default: INVALID, and INVALID is an ERROR.** Previously the
  out-of-set default was `NONE`, which is the *safe-looking* answer and
  therefore the dangerous one -- absence and unevaluable are different claims.
- **Not allowlistable:** INVALID errors regardless of allowlist membership,
  unchanged from #2310.
- **Both sides covered:** the two admitted values and six rejected ones are
  pinned in the same table.

### Boundary-change enumeration

- Boundary path/seam: `id-token` scalar classification.
- Replaced-path behaviours: unrecognized scalars move from `NONE` (silent) to
  `INVALID` (ERROR). `write` and `none` are unchanged.
- Guard-relevant fields: the `id-token` value at workflow and job scope.
- Caller x input shape: predicate x {recognized, unrecognized, templated,
  empty, case-variant, whitespace-padded}; auditor x the real workflow tree.

**Reachability proof:** `test_workflow_scope_invalid_id_token_errors_on_its_own`
drives the full `audit_workflow` and asserts exactly one error, so the finding
cannot be supplied by another branch.

## Mechanism

An if/elif over a two-value vocabulary, replacing a binary comparison with an
`else`.

## Intentional

- **Closed vocabulary rather than a longer denylist.** The recurring failure
  here is a catch-all mapping unknown inputs to the safe-looking answer.
  Enumerating what is *allowed* makes the unknown case reject by construction.
- **`read` is rejected, not treated as harmless.** GitHub documents `write` and
  `none` for this scope; `read` is not a value it accepts, so admitting it would
  mean the auditor understands the config better than GitHub does.
- **Case and whitespace variants reject.** YAML preserves both, and a config
  that GitHub would reject should not be silently forgiven by the auditor.

## Also in this PR: restoring six unit-gate baseline entries

Not related to the OIDC predicate, but it is blocking this PR and every other
PR against `main`, so it is fixed here rather than filed.

ATLAS #2303 removed six `tests/test_b2b_reviews_import.py` nodes from
`tests/unit_gate_baseline.txt` on the grounds that they had started passing. The
evidence for that was three runs of `pytest tests/test_b2b_reviews_import.py` --
the file **in isolation**. The unit gate runs the whole `tests/` tree, and in
that context they still fail, so the removal turned six known failures into six
regressions.

Because the baseline is on `main`, every PR opened against it inherits those six
regressions. CI being down when #2303 merged is why this went unnoticed for
hours: there was no unit-gate run to contradict it.

Restored verbatim. The lesson recorded rather than just the fix: *passing in
isolation is not evidence of passing in the suite*, and a known-failures list
must only shrink on evidence gathered the way the gate gathers it.
