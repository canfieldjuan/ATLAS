# PR-Skip-Delete-Push-Review

## Why this slice exists

After PR #2321 merged, post-merge cleanup ran `git push origin --delete
claude/pr-local-unit-gate-mirror`. After PR #2323 merged, cleanup repeated the
same failure mode while deleting `claude/pr-unit-gate-baseline-shrink`: the
managed local pre-push hook treated the branch-delete push as a normal PR
publication path, ran `scripts/local_pr_review.sh`, and reached the local
unit-gate mirror with no changed files. The selector escalated to `FULL`,
burning full-suite time during branch cleanup. The operator asked to continue in
the workflow/pr-enforcement lane, and this is the next concrete friction point
from that lane.

### Problem-derived contract

- Root cause: The managed pre-push hook generated by
  `scripts/install_local_pr_hook.sh` ignores the pre-push stdin ref update list,
  so delete-only pushes run the same local review path as a code publication push
  even though they cannot introduce a PR diff.
- Correct fix must touch/change: `scripts/install_local_pr_hook.sh` must generate
  a hook that reads the pre-push ref updates, detects delete-only pushes, exits
  successfully with an explicit skip message, and still runs
  `scripts/local_pr_review.sh` for normal pushes, mixed push/delete updates, empty
  manual hook invocations, and the existing explicit skip env.
  `tests/test_install_local_pr_hook.py` must prove those hook behaviors.
- Must not change: Do not change `scripts/local_pr_review.sh`, `scripts/push_pr.sh`,
  `scripts/open_pr.sh`, branch protection, unit-gate behavior, product code, or
  any EOM/customer-visible surface.

## Mechanism

The generated pre-push hook first preserves explicit operator skip and
interactive/manual invocation behavior. If stdin is a TTY, the hook immediately
executes local review instead of waiting for ref-update input. For non-TTY stdin,
it reads each physical stdin record before tokenization, including a final
nonempty record that reaches EOF without a trailing newline. It tracks whether
any ref updates were supplied and treats whitespace-only records as malformed. A
delete update is identified only when Git's
all-zero local SHA, the `(delete)` local ref marker, a remote `refs/*` ref
accepted by `git check-ref-format`, and a non-zero forty-hex remote object name
appear together after the hook has validated that the record has exactly four
fields. If at least one update was supplied and none were non-delete, malformed,
or conflicting-marker updates, the hook prints an explicit delete-only skip
message and exits 0.
Otherwise it falls through to the existing local-review execution path.

## Intentional

- Mixed pushes still run local review. That keeps the bypass limited to cleanup
  pushes and avoids treating a branch delete bundled with a real branch update as
  safe.
- No change to `scripts/push_pr.sh`; PR publication should continue to use the
  managed hook or wrapper review path exactly once.
